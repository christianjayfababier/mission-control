    Select a project

    Pick a project on the left. A terminal opens in its directory; run claude there to start the orchestrator. Workers it spawns appear below.
    Workers

    Repository & GitHub account

    The account's token and identity are set in the environment of every new terminal for this project (GH_TOKEN, GIT_AUTHOR_*/GIT_COMMITTER_*), so gh and git push act as that account while other projects keep theirs. Existing terminals keep their old identity: close and reopen them.

    Team & models

    Each role runs at a model and effort. Custom roles come from the project's .claude/agents files and are saved back there; built-in types are stored by Mission Control and handed to the lead. Leave a field empty to let the lead decide. The lead may still escalate a stuck worker to Fable.

    AI Collaboration

    Which AI tools and API keys this project's lead and workers may use. Switch one off and its key stays out of every new terminal Mission Control opens here; the key itself is kept, and other projects still get it. Installing a tool, logging in and pasting a key all live in Settings → Accounts & AI, behind the cog at the bottom of the sidebar.

    Settings

    The tools Mission Control and its workers run, and the keys they run with. Logins and installs open in a terminal of the selected project, where you can answer their prompts. New terminals pick up a saved key; terminals that are already open keep the environment they started with.

    Your own additions to the orchestrator rulebook. They are appended to every lead session's system prompt, after Mission Control's own rules and before the project block, in every project. Mission Control never overwrites this file. A lead that is already running keeps the prompt it started with: changes reach it at its next launch.

    Projects you hid from the sidebar. Mission Control still remembers them and everything it ever saw in them; hiding only takes them out of the list. Pinned projects are never hidden.
